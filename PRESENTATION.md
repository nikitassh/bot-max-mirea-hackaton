# Тикет-бот для мессенджера МАСК
### Система обработки обращений студентов — хакатон-проект

---

## Проблема

Студенты пишут преподавателям в личку — вопросы теряются, дублируются, забываются.  
Нет единого места, нет истории, нет прозрачности ни для одной из сторон.

**Результат:** преподаватель перегружен, студент ждёт ответа неизвестно сколько.

---

## Решение

**Тикет-бот прямо в МАСК** — мессенджере, которым уже пользуются все.  
Студент создаёт обращение в два нажатия. Преподаватель видит очередь, работает с каждым тикетом, отвечает или назначает консультацию. Всё фиксируется автоматически.

> Не новое приложение. Не новый сайт. Просто бот там, где все уже есть.

---

## Для кого

| Роль | Что получает |
|---|---|
| **Студент** | Простой способ задать вопрос, отследить статус, получить ответ |
| **Преподаватель** | Структурированная очередь, история, ИИ-помощник, аналитика |
| **Университет** | Прозрачность всех обращений, статистика, GDPR-совместимость |

## Как это работает — путь студента

### 1. Онбординг (один раз)
- Бот показывает **политику конфиденциальности** и условия использования
- Студент **принимает соглашение** — факт и версия фиксируются в БД
- Выбирает роль: **студент** или **преподаватель**
- При каждом `/start` — чат очищается, онбординг показывается заново

### 2. Создание обращения — два пути
**По семестру:**
- Выбирает семестр (1–8, 2 ряда по 4 кнопки)
- Выбирает дисциплину из 8 вариантов
- Видит только преподавателей этой дисциплины (1–2 человека)

**По преподавателю:**
- Вводит имя преподавателя текстом
- Бот находит совпадения и показывает список

### 3. ИИ-фильтрация до создания тикета
Если у преподавателя есть **база знаний** — бот проверяет, можно ли ответить автоматически.  
Если ответ найден — студент получает его мгновенно, тикет не создаётся.  
Это разгружает преподавателя от повторяющихся вопросов.

### 4. Защита от дублей
Перед созданием ИИ проверяет открытые тикеты студента.  
Если найден похожий — предлагает посмотреть его, а не создавать новый.

### 5. Подтверждение и создание
Студент видит итоговую карточку: преподаватель, категория, текст.  
После подтверждения — тикет создан, преподаватель получает уведомление.

### 6. Отслеживание статуса
Студент видит все свои обращения и полную **историю действий** по каждому:
- Создано → Принято в работу → Ожидает уточнения → Закрыто

## Как это работает — путь преподавателя

### Главное меню с живыми счётчиками
```
📋 Очередь (3 новых)
🔄 Активные тикеты (5)
✅ Закрытые тикеты (12)
📚 База знаний
📊 Статистика
```

### Очередь новых обращений
Каждый тикет показывает: номер, имя студента, категория, ИИ-саммари вопроса.  
Кнопки: **Принять в работу** / **Открыть**.

### Работа с активным тикетом
Для каждого тикета доступно:
- 💬 **Ответить и закрыть** — ввести текст ответа, выбрать итог (решено / перенаправлено / отказано)
- ❓ **Запросить уточнение** — выбрать нужные поля (репозиторий, группа, скриншот, тема) + комментарий
- 📅 **Назначить консультацию** — предложить 2–3 временных слота, студент выбирает удобный
- 💡 **ИИ-ответ из базы знаний** — бот генерирует ответ на основе загруженных материалов
- 🔒 **Закрыть** с комментарием

### Активные тикеты
Список в формате: `#ID · Категория · Фамилия студента`

---

## База знаний — как статьи

Преподаватель ведёт собственную базу знаний в виде **статей**:
- У каждой статьи есть **название** и **описание**
- Список статей с кнопками ✏️ и 🗑 прямо в строке
- Можно добавлять, редактировать, удалять отдельные статьи
- ИИ использует все статьи при поиске автоответа для студента

---

## Статистика — живой дашборд

При нажатии «Статистика» бот **генерирует PNG-график** и отправляет прямо в чат.

### Что на графике:
| Виджет | Содержание |
|---|---|
| **KPI-карточки** | Всего тикетов · Активных · Закрыто |
| **Доп. метрики** | Новых · Среднее время закрытия · % полезных ответов |
| **Bar chart** | Распределение тикетов по категориям |
| **Pie chart** | Распределение по статусам |
| **Line chart** | Активность по дням за последние 14 дней |

> Всё в тёмной теме, в один клик, без переходов на сторонние сервисы.

## Уведомления — двусторонние

| Событие | Кто получает | Что |
|---|---|---|
| Новый тикет | Преподаватель | Уведомление + кнопки действий |
| Принято в работу | Студент | Подтверждение |
| Запрос уточнения | Студент | Список полей + кнопка ответить |
| Студент ответил | Преподаватель | Текст ответа + кнопка к тикету |
| Тикет закрыт | Студент | Ответ преподавателя + оценка полезности |
| Слоты консультации | Студент | Кнопки с вариантами времени |
| Слот выбран | Преподаватель | Какой слот выбрал студент |

## ИИ-возможности

Все запросы через **OpenRouter** (совместим с OpenAI API):

| Функция | Как работает |
|---|---|
| **Автоответ** | Проверяет базу знаний преподавателя до создания тикета |
| **Антидубль** | Сравнивает новый вопрос с открытыми тикетами студента |
| **Саммари** | Генерирует краткое описание тикета для очереди преподавателя |
| **ИИ-ответ для преподавателя** | Предлагает готовый ответ на основе базы знаний |

---

## Учебный план — 20 преподавателей, 8 семестров, 64 дисциплины

Бот содержит **полноценный учебный план**:
- 8 семестров
- По 8 дисциплин в каждом
- За каждой дисциплиной закреплены 1–2 конкретных преподавателя

Студент идёт по маршруту **Семестр → Дисциплина → Преподаватель** — и видит только тех, кто ведёт его предмет.

---

## Защита данных

- Согласие на обработку фиксируется в БД с версией документа и временем
- Студент может **удалить все свои данные** в любой момент (тексты обнуляются, привязка удаляется)
- Анонимная статистика сохраняется
- Политика конфиденциальности и условия использования — прямые ссылки из интерфейса
